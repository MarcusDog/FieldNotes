# 后续开发的技术提示词模板

这里提供可复用的技术模板，不计入已经发生的 Prompt。实际对话原文按顺序保留在根目录 `AI_LOG.md`。今后使用模板时，先填入当前事实，再将实际发出的全文追加到日志。

## 通用结构

```text
任务目标
说明需要改变的行为和完成条件。

项目背景
写明技术栈、版本、运行平台、相关文件和接口契约。

现有证据
粘贴可复现步骤、预期结果、实际结果和脱敏日志。
区分已确认事实与待验证假设。

约束
列出兼容要求、允许改动的范围、数据保护要求和不做的扩展。

交付内容
列出需要修改的源码、文档和验证记录。

验收标准
给出可以观察或执行的检查，说明成功与失败分别是什么。

验证与汇报
先运行相关检查，再报告结果、剩余问题及证据路径。
不能把源码存在、编译通过或模拟结果写成真机验收通过。
```

## Go 接口开发示例

```text
任务目标
完成问题创建、列表和状态更新 API，并在服务重启后保留数据。

项目背景
Go 1.26，标准库 HTTP，单进程本地 JSON 存储。
字段与 docs/SPEC.md 一致，Unity 和 React 使用同一个服务。

约束
标题必填；priority 为 low/medium/high；状态为 open/in_progress/resolved。
后端生成 ID、UTC 时间和默认 open 状态，要求完整且有限的三轴坐标。
持久化失败不得更新内存或返回成功，损坏文件不得静默当成空库。

交付内容
修改 server/ 中的实现与必要测试，更新接口文档。

验收标准
执行 go test -race、go vet 和 scripts/smoke.sh。
实际创建并更新问题，重启进程，确认同一 ID 和状态仍存在。
非法参数需返回明确的 400 错误；使用独立测试数据，保留现场数据。
```

## Unity 真机故障排查示例

```text
任务目标
定位并修复 iPhone 上的具体故障，保持真实 AR 平面检测与放置流程。

项目背景
Unity 6000.3.27f1 LTS，AR Foundation/ARKit 6.0.8，iPhone 15 Pro Max。

现有证据
复现步骤：[填入实际操作]
预期结果：[填入可观察行为]
实际结果：[保留手机上的原始提示]
设备日志：[粘贴脱敏片段]

约束
先检查权限、XR 加载器、导出原生文件与签名包，再提出修改。
不得用普通 3D 场景、固定屏幕物体或模拟坐标代替真实 AR。
不读取或提交签名凭证；需要现场观察的步骤明确交给本人确认。

交付内容
最小修复、相关回归检查、原因说明和真机复验步骤。

验收标准
通过 Unity 测试、iOS 导出与 Xcode 构建；设备日志验证修复路径。
由本人确认现场画面、平面、标记和 UI 操作，再记录真实结果。
```

## 提交前检查示例

```text
任务目标
整理可公开下载的 Unity、Go、React 源码与文档，保留完整 Git 历史。

约束
AI_LOG 保留实际 Prompt 原文，仅对敏感信息使用明确占位符。
不改写历史 Prompt，不编造测试、人工检查或录像。
排除业务数据、设备标识、证书、账号凭证、缓存和构建产物。

交付内容
简短 README、AI_LOG、验证记录、录像步骤、公开仓库链接。

验收标准
执行项目测试，核对 Git 历史与公开下载权限。
逐项列出已完成、未完成和已知问题；录像未完成时明确标记。
使用清楚自然的中文，依据代码和实际操作说明结果。
```
