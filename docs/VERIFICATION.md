## 现场反馈与修正

### 编辑器版本与磁盘空间

用户指出磁盘不足，并询问是否必须使用 6000.0。核实后放弃并行安装多个编辑器，按用户授权卸载 6000.6.7f1，改用 6000.3.27f1 LTS 和 iOS 模块。最终项目使用这一套 LTS。

### 相机授权

用户报告“相机未授权”，系统设置也没有开关。检查导出的原生代码发现 `UNITY_USES_WEBCAM=0`，Unity WebCam 授权路径被编译为空实现。新增最小 AVFoundation 桥接，只查询和请求权限，画面仍由 ARKit 提供。更新签名包后，设备日志确认授权成功，用户随后确认已有相机画面。

### ARKit 插件未进入导出工程

用户报告“此环境没有可用的ar kit”。设备日志出现 `Unable to load plugin UnityARKit`，导出目录缺少 `UnityARKit.m` 与 `libUnityARKit.a`。对照已安装的 ARKit 6.0.8 源码，发现批量构建依赖预先存在的 `UNITY_XR_ARKIT_LOADER_ENABLED`。

配置现在保存该符号，脚本先配置，再用新 Editor 进程导出，并检查原生文件是否存在。修正后的导出、Xcode 构建与签名校验通过，设备启动真实世界跟踪，随后收到实际手机记录。

### 地址与平面

用户先报告地址无效，后确认恢复。未取得出错时的原始输入，不能认定具体原因；补充了省略协议、全角标点和不可见复制字符的处理及回归测试。

平面模板最初的 `activeSelf=false` 会被克隆对象继承。修正为放在隐藏父对象下、模板本身保持 activeSelf，并加入回归断言。当前平面由 8 mm 绿色边界线显示，用户曾反馈不易看清，已说明线内是可放置区域。

### 数据与测试

审查补充了标题/描述 Unicode 长度限制；损坏或不完整 JSON 拒绝启动；单端口同源 PATCH 的 CORS 判断按实际 Host/TLS 处理。对应测试通过。

Unity 首轮测试曾错误依赖 float 的固定小数文本，现改为解码后的数值容差比较。EditMode 网络测试显式等待原生异步操作；生产代码保留标准 Unity 协程流程。
